# VOY 2026 Sponsor Replies, GoTyme QR and Donation Verification

## Included
- Public personalized sponsor page: payment instructions and original payment QR extracted from the uploaded Donation & Sponsorship Information PDF.
- Cash / in-kind / pledge / decline response form, with optional proof upload (JPG, PNG, PDF, max 5MB).
- Random submission tracking ID, with status lookup on the personalized sponsor link.
- Officer dashboard > Sponsor responses; finance/admin can inspect private proofs and verify or reject cash/in-kind contributions.
- Verified contributions are inserted in the existing `donations` ledger and get a printable *contribution acknowledgment* (not a BIR official receipt or tax document). A submission confirmation is not a receipt.

## Setup steps
1. Back up your Supabase database and review the new policy changes before using real donor data.
2. In Supabase SQL Editor run `supabase/DONOR_REPLY_AND_QR_MIGRATION.sql` **after** the original schema and personalized link/category migrations. Do not rerun old, broken versions of SQL.
3. Upload the entire contents of this project to the root of your existing `amicusupm/VOY-2026` GitHub repository. Keep your established GitHub Actions variables `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` and select GitHub Actions as the Pages source. The workflow builds `dist`.
4. Test: create a *test* solicitation while logged in; open the personalized link in a private browsing window; submit a test response and proof; copy the submission ID; log into the private dashboard and open Sponsor responses; verify the test contribution; look up its ID in the sponsor page and print the acknowledgment.
5. Verify payment destination and QR with the finance team before sharing any public link. The document identifies GoTyme, Chelsea Joy B. Redondo, 0143-1671-4802. The QR is copied from the supplied document, **not regenerated**.

## Security and limitations
- The Supabase `donation-proofs` bucket is **private**: public visitors can upload permitted file types, but cannot read/list proofs. Authorized finance officers use short-lived signed URLs.
- Any public upload feature can attract automated/spam submissions. Add CAPTCHA, server-side rate limiting, retention policy and malware scanning before broad production use. This version has input limits and storage file size/MIME restrictions but **does not implement those advanced controls**.
- Use only approved finance accounts, and never ask for card PINs, banking passwords, OTPs, or full account statements.
- The response submission ID is a bearer secret. Keep it private. It can be used together with the sponsor link to retrieve the submission's verification status and acknowledgment.
- The acknowledgment is generated by the web page only after finance validation. It is **not a legally recognized official receipt**. Official receipts must be issued separately if required.
- Donation receipt proof images are uploaded to storage and linked by `proof_path`. Officers should never share the storage path publicly. Additional validation of ownership between uploaded file and response should be done server-side for higher assurance.
- This implementation has not been production-tested against your live Supabase project. Run a complete end-to-end test before relying on it for money collection.
